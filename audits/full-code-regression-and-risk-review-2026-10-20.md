# Tokyo Concierge Atelier · full code and data regression audit · 2026-10-20

Base `f07717b508dd79789959d5859748f536203b607b`. This audits existing static site, 131 venue rows, 89 registered real-photo records, 42 not yet approved original-venue photos, 50 pre-existing AI illustrative images, photo copyright ledger, six workflows and research scripts. **Do not claim the entire external web or all unknown browser environments can be proved free of errors**; distinguish confirmed code faults from external-site instability.

## Verified code and data inconsistencies

1. **a32 catalogue address mismatch.** Kimono Photo Studio WA was labelled Asakusa in actual `DATA` and `audits/missing-photo-queue.csv` even though its navigation had a special-case Meguro address. The studio's official [access page](https://kimono-wa.com/en/access.html) confirms Kamiosaki 2-24-13, Shinagawa-ku, Meguro Station west exit. Corrected `area` to Meguro, regenerated the active missing-photo queue row and refreshed localized original-source details and warning. Retained the correct explicit building/room map destination. The previous a32 photo gate was permanently blocked even after an address correction; now it requires a new image's own **actual Meguro photographic evidence and copyright grant** before allowing any new photo.
2. **Shortlist persistence consistency.** The previous app had no `storage` listener, so updates in a second tab were not displayed in the first tab's shortlist or open details. Added a controlled, validated parser of venue IDs, cross-tab state synchronization and detail button refresh, and a safe fallback for malformed JSON. Kept guest data out of the browser storage.
3. **False saved status on Safari private/quota-blocked storage.** The previous `save()` silently swallowed `localStorage.setItem()` failures, implying an item would be available after reloading. Added a localized guest-facing notice that data may disappear when the page closes and advises copying the guest guide link. This notice takes precedence over transient 'Added' messaging when saving actually failed.
4. **Stale share state and early download cleanup.** The original 'Link copied' button label remained after changing the selected venues; saving a new shortlist now resets the button to 'Copy guide link'. Object URLs for exported CSV were revoked after only one second; increased to 30 seconds to avoid invalidating a slower iOS/Safari download. No guest details are exported; existing formula-injection guard is preserved.
5. **Unsafe alternative Commons script classifications.** `scripts/find-photo-candidates.mjs` previously flagged CC BY-ND and unspecified Public domain as suitable rights candidates; a generic photo is never a license to illustrate a specific venue. It also retried 429/503 up to **four times**, creating avoidable rate-limit pressure. Candidate types now only recognise CC0/CC BY/CC BY-SA, are explicitly `venueMatch: UNVERIFIED`/`reuseApproved:false`, and stop further network requests on the first rate-limit/service refusal. Unsearched venues get DEFERRED_API_RATE_LIMIT, not falsely 'no usable photo'.
6. **Competing automated image workflows could publish without review.** `generate-venue-ai-images.yml`, `map-uploaded-ai-concepts.yml`, and `publish-ai-raster.yml` had direct `git push`/automatic commit workflows and write permissions. Converted each to read-only **manual review with artifacts**, no unattended pushes. Separate photo candidate research was launched on ordinary changes to `missing-photo-queue.csv` and its script; changed it to manual-only, avoiding four different sources of hidden work/races. The main weekly Commons audit and website's own Pages deployment are left intact.
7. **Wrong venue prompts could propagate misleading images.** Corrected 22 generator prompt descriptions with the actual place's type/area (notably Ginza sumo, Ryogoku sumo souvenir, Meguro kimono, sake-tasting, Ginza immersive dining, Minami-Aoyama yakiniku, Daikanyama Italian, Marunouchi French, conveyor sushi). Blocked future generation for the **closed r31** and **invitation-only r52**. Every generated work is explicitly an illustration, **not an original-venue photograph**. The existing generated 50 WebP assets and 89 approved photographs are unchanged.
8. **Regression coverage gaps.** Added `tests/state-regression.cjs` for Meguro filter/detail, other-tab saved IDs, invalid storage, stale copied-link label and blocked-storage browser exception. The same tests run in Chromium against local HTML and deployed Pages. Added `tests/audit-pipeline-safety.cjs` for manual-only AI workflows, 429 circuit breakers and corrected semantic prompts. `tests/audit-venues.cjs` now enforces exact area identity. CI also checks Python generator and JavaScript research script compilation.

## Existing external-link audit: not all 131 external venues passed HTTP 200

Prior actual Github Actions Browser smoke QA #39365243399 reported `HTTP_OK=125, ACCESS_RESTRICTED=4, NETWORK_ERROR=1, HTTP_ERROR=1`; notable responses were `r06` 403, `r11` 403, `r38/r39` 403, `w02` 503 and `a06` network error. These **do not establish a broken site rendering** and can reflect bot blocking or temporary upstream outages. Never redirect guests to invented replacement businesses or URLs solely from one transient check. Keep the venue records and real exact-site links until independently confirmed. The external audit should continue to disclose non-2xx outcomes instead of being described as 131/131 valid.
