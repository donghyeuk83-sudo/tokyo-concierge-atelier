# Tokyo Concierge Atelier — Designer's mobile workflow and browser compatibility audit

Date: 2026-10-20. Starting main: `128ab0673bba829901d97bbcf0677bf5a916ea98`.

## Objectives (evidence-based)

1. **Make the core guest task visible first.** The existing mobile homepage showed a dramatic hero and multiple long photo/editorial galleries before the searchable 131-place catalogue, even though the audience's core job is guest place lookup and building recommendations. Preserve the cinematic brand, photos and typography, but use a more compact hero, clear first-viewport **FIND PLACES** CTA, condensed three-category choices, and move the existing working catalogue/shortlist directly after the introductory category buttons *only on devices 720px or narrower*. Desktop retains the original ordering. Moving the actual DOM node (not CSS visual-only order) preserves screen-reader and keyboard navigation order as well as event listeners.
2. **Full entry-screen localization.** The language selector originally translated catalogue controls but left hero CTA, category tile headings/subtitles, catalogue verification explanation and outdated English footer partially untranslated. Set these UI strings consistently in EN/JA/KO on each language change. Footer says when **site code** was updated, not that external restaurant opening hours or copyright claims were reverified.
3. **Improve iPhone CSV delivery.** A recent main automated Chromium+WebKit run [#39377641740](https://github.com/donghyeuk83-sudo/tokyo-concierge-atelier/actions/runs/39377641740) created a genuine GitHub health alert [#38](https://github.com/donghyeuk83-sudo/tokyo-concierge-atelier/issues/38) after WebKit iPhone emulation didn't dispatch a `download` event for a dynamically created Blob anchor. Keep the generated CSV, formula-sanitization, Japanese text, UTF-8 BOM and client-only/no guest data behavior. Attach the anchor to the DOM for the automatic attempt, and maintain a **visibly tappable same-origin Blob download link** with localized "Open CSV" message for Safari or other browsers where the automatic event is suppressed. Retain the Blob until the next export or page exit instead of revoking after 30 seconds, preventing accidental stale links.
4. **Verify the actual output rather than relaxing quality standards.** On iPhone WebKit, an automatic download event may be blocked by device emulation itself; test the Blob's real original bytes, UTF-8 BOM, CSV header and selected venue, plus visible manual link. If the browser does deliver a native download event, also assert that file. This distinguishes file-production correctness from the emulator's download notification and does not incorrectly assert a native download happened.

It checks first-fold CTA, screen width, actual catalogue before inspiration on mobile, original desktop editorial ordering, live resize/rotation, zero lost shortlisted venues, all three translated strings, category shortcut controls and no JS errors.
- Existing `tests/webkit-mobile.cjs` retains search, photo filters, actual cross-tab shortlist sync, persisted language, source/attribution, blocked storage and detail dialogs. Expanded CSV assertions validate actual Blob bytes and manual click target even if emulation prevents an automatic download event.
- Existing `tests/smoke.cjs` Chromium and all upstream photo/source audits remain active. The [daily production health workflow](https://github.com/donghyeuk83-sudo/tokyo-concierge-atelier/pull/37) is installed on main and will file at most one actionable, deduplicated GitHub issue per unresolved failure; successful main QA closes it. There is no unattended repository code write/merge or licensed-photo rehosting.
- Preserve all **131** venue records, **89** licensed photo mappings, **42** not-yet-approved originals, **46** source links, **50** existing AI illustrations, design media and printed guide semantics. No image or guest data change. Real iPhone device hardware testing is not asserted by WebKit emulation.
